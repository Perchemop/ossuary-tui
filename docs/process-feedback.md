## 2026-11-06 — first build session

What I was trying to do: stand up a brand-new Rust TUI app (Ossuary) from the
guide, with no local toolchain and no pre-existing repo.

Block or friction: the guide requires a committed `Cargo.lock` (§II.28, K.14)
but the machine cannot run `cargo`, so the lockfile can only be generated by CI.

Suggested change: note in §K.11 that a new repository may bootstrap its
`Cargo.lock` by uploading the CI-generated lock as an artefact and committing
it in a follow-up; that is the workaround used here.

Severity: slows-work

Workaround used: the `check` job uploads `Cargo.lock` as `ossuary-cargo-lock`;
it is committed after the first green run.

Confirm: did NOT violate clean-room / v0.1.0 gate / no-secrets /
CI-before-client-try / no meta-guide push.
